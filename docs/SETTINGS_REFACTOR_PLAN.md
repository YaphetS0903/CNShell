# CNshell 设置中心重构规划

## 背景与目标

当前设置页把 15 组功能全部纵向渲染在一个长表单中，用户必须滚动到底部才能保存；普通用户会在首次打开时看到 MCP、团队服务、插件、协议探测和自动化等高级能力，信息密度过高，也让设置页启动时同时触发大量环境检测。

本次重构目标：

1. 普通用户打开设置后，第一屏只看到最常用的外观、终端和会话选项。
2. 所有设置按用户任务分组，单个分类内容控制在一个可理解的滚动区域内。
3. 保存、取消和未保存状态始终可见，不需要滚动到底部。
4. 高级能力继续完整保留，但采用渐进式披露，不在基础分类中打扰用户。
5. macOS 和 Windows 使用同一信息架构，支持键盘导航、焦点管理、浅色/深色/高对比主题。
6. 只有当前分类才挂载需要网络或环境探测的组件，降低打开设置时的开销和副作用。

> 实施状态（2026-09-01）：Phase 1 已完成。设置页已使用分类导航、按需挂载、固定保存栏、未保存提示和关闭确认；Phase 2/3 保留为后续迭代。

## 新的信息架构

### 1. 基础设置（默认打开）

- 外观：主题。
- 终端：字体、字号、行高、回滚、光标和配色。
- 会话与文件：监控刷新、命令历史、关闭确认、隐藏文件、启动帮助。
- 顶部显示“修改尚未保存”状态；底部固定“取消 / 保存设置”。

### 2. 连接与安全

- OpenSSH 配置与密钥。
- 高级协议与转发。
- 代理与跳板机。
- 连接库备份。

### 3. 自动化与集成

- 受限自动化与定时任务。
- AI 辅助。
- MCP 服务。
- 插件。

### 4. 团队与云端

- 加密同步。
- WebDAV 同步。
- 团队工作区与 RBAC。
- 在线团队服务。

### 5. 关于与支持

- 软件更新。
- 反馈与诊断。

## 交互方案

### 桌面布局

```text
┌──────────────────────────────────────────────────────────┐
│ 设置                                               [×]   │
├──────────────┬───────────────────────────────────────────┤
│ 基础设置     │ 基础设置                                  │
│ 连接与安全   │ 当前分类说明                               │
│ 自动化与集成 │ ┌───────────────────────────────────────┐ │
│ 团队与云端   │ │ 当前分类内容（独立滚动）                │ │
│ 关于与支持   │ └───────────────────────────────────────┘ │
│              │                                           │
│              │ [未保存提示]             [取消] [保存设置] │
└──────────────┴───────────────────────────────────────────┘
```

- 左侧为带图标的分类导航，当前项使用主题色和背景强调。
- 每个分类显示简短说明；窄窗口降级为顶部可横向滚动的分类条，不产生页面横向滚动。
- 保存栏使用 `position: sticky` 固定在内容底部，按钮保持至少 44px 高度。
- 分类切换不会自动保存；如果存在修改，切换分类不丢失草稿。
- 关闭设置时如果有未保存修改，先确认“放弃修改 / 继续编辑”。
- 复杂子模块内部继续使用现有卡片和“保存 Provider / 保存授权 / 上传”等局部操作；底部“保存设置”只负责全局 AppSettings。

### 渐进式披露

- 基础设置不挂载高级模块，避免打开页面就进行协议、MCP、团队和云同步探测。
- “连接与安全”“自动化与集成”“团队与云端”进入分类后才加载对应模块。
- 高级模块内部保留现有安全警告、确认框和局部保存按钮，不降低权限边界。
- 分类导航使用 `aria-current="page"`；内容区使用 `role="tabpanel"` 和对应 `aria-labelledby`。

### 响应式与可访问性

- 桌面宽度：导航 168px，内容区最大宽度 760px。
- 小于 720px：导航变为可滚动的 segmented tabs，内容区占满宽度。
- 所有图标按钮必须有可读 `aria-label`；Tab 顺序遵循导航 → 内容 → 底部操作。
- 保留可见 focus ring、Esc 关闭、模态焦点陷阱和 `prefers-reduced-motion`。
- 成功/错误状态使用文字和图标，不仅依赖颜色；toast 继续 5 秒自动消失。

## 数据与状态策略

1. `draft` 仍由 `SettingsModal` 持有，分类切换只改变视图，不重置草稿。
2. 使用 `settingsDirty`（深比较 `draft` 与 `settings`）控制未保存提示、关闭确认和保存按钮状态。
3. 当前分类使用本地 state；以后可从 URL/深链接恢复，但本轮不引入路由依赖。
4. 高级模块按分类懒挂载。切换离开后保留分类组件状态，避免编辑中的 Provider、MCP 授权或同步配置丢失。
5. 现有 API、权限确认、凭据存储和局部保存行为不改变。

## 分阶段实施

### Phase 1：设置壳层（本轮）

- 新增分类导航、分类标题和说明。
- 将基础设置作为默认分类。
- 将现有模块按信息架构分组，并按需挂载。
- 固定底部保存栏，增加未保存状态与关闭确认。
- 更新组件测试，覆盖默认分类、分类切换、保存和未保存关闭确认。

### Phase 2：模块内整理

- 将连接与安全中的四个模块统一为一致的卡片标题、说明和局部操作区。
- 将 MCP、团队、同步等长模块增加二级折叠区和“危险/高级”标识。
- 统一按钮文案、加载状态、错误恢复和空状态。

### Phase 3：体验与性能

- 进一步拆分每个高级模块的懒加载 chunk。
- 增加设置搜索（仅搜索当前已注册字段，不读取凭据值）。
- 增加“恢复默认基础设置”操作和逐项帮助链接。
- 在 macOS/Windows 真机验证高 DPI、键盘、VoiceOver/Narrator、深浅色主题和窄窗口。

## 验收标准

- 打开设置首先看到基础设置，首屏不出现 MCP、团队、插件或协议探测卡片。
- 任意分类都能在不滚动到底部的情况下看到取消和保存按钮。
- 切换分类后草稿值保持；保存成功后关闭，取消不写入设置。
- 有未保存修改时点击关闭会给出明确确认；放弃后恢复原值。
- 15 组现有功能入口仍可访问，现有安全确认、API 调用和局部保存测试不回归。
- `npm run lint`、`npm test`、`npm run build` 通过；新增设置导航和关闭确认回归测试通过。

## 暂不改变的内容

- 不删除任何现有设置功能。
- 不改变 AppSettings、数据库、Keychain/Credential Manager 或 MCP 权限模型。
- 不把高级协议、团队服务或云同步默认打开。
- 不在本轮引入新的账号体系、远端服务或跨平台原生控件依赖。
